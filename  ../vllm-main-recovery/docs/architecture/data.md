# 데이터 아키텍처

## 문서 목적

데이터 영역의 소유권, 시스템 사이의 흐름, 일관성 및 수명 주기 원칙을 설명합니다. 모든 테이블과 필드를 Markdown으로 복제하지 않습니다.

## 언제 수정하는가

- 데이터 소유자, 기준 저장소 또는 전달 경로가 바뀔 때
- 핵심 불변 조건, 일관성 또는 트랜잭션 정책이 바뀔 때
- 개인정보 분류, 보존 또는 삭제 정책이 달라질 때

## 작성할 내용

- 데이터 영역과 소유 구성 요소
- 생성·변경·전달·삭제 흐름
- 핵심 불변 조건과 일관성 경계
- 보존 기간, 민감도, 암호화와 삭제 정책

## 최소 예제

| 데이터 영역 | 소유 구성 요소 | 기준 저장소 | 보존 기간 | 민감도 |
|---|---|---|---|---|
| 작성 필요 | 작성 필요 | 작성 필요 | 작성 필요 | 공개 / 내부 / 기밀 |

## 핵심 불변 조건

- 항상 참이어야 하는 업무 규칙을 작성합니다.

## 데이터 흐름

데이터의 생성, 변경, 전달, 삭제 경로를 작성합니다.

## 개인정보와 보안

수집 목적, 최소 수집, 암호화, 마스킹, 삭제 정책을 작성합니다.

실제 테이블 구조는 마이그레이션 또는 DDL을 기준으로 삼고, 의미 설명은 [데이터베이스 명세](../specs/database/README.md)에 둡니다.
