# 공통 개념

## 문서 목적

여러 구성 요소가 일관되게 따라야 하는 횡단 설계 원칙을 설명합니다. 정확한 API나 스키마 계약은 기술 명세에 둡니다.

## 언제 수정하는가

- 인증, 권한, 오류, 로깅, 관측성 같은 공통 정책이 바뀔 때
- 여러 구성 요소에 반복되는 구현 방식이 표준화될 때
- 보안 또는 개인정보 처리 원칙이 달라질 때

## 작성할 내용

- 인증과 권한
- 오류 분류와 전파
- 로깅, 추적, 메트릭
- 설정, 비밀 값, 시간과 식별자 처리
- 캐시, 재시도, 멱등성 등 공통 정책

## 최소 예제

| 개념 | 공통 원칙 | 예외 처리 |
|---|---|---|
| 요청 식별자 | 모든 외부 요청에 식별자를 부여하고 하위 호출로 전달 | 배치 작업은 실행 식별자 사용 |
